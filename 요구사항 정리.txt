산행용 관리앱을 만들고 싶은데 다음 조건을 수용하는 형태로 만들고 싶어.

[개별적인 도메인]
- 무료 도메인 서비스를 통해서 시범서비스를 만들예정

[서비스명 ]
Climb My Own

[구조 요구사항]
- 기능 단위로 폴더 분리, 파일 하나당 책임 하나
- UI 렌더링 / 상태 관리 / 데이터 저장 계층을 분리
- 저장 방식을 나중에 서버 API로 교체해도 UI 코드는 수정 불필요하게
- 새 기능 추가 시 파일을 어디에 두면 되는지 규칙이 명확할 것
- 레이어별 분리 — UI / 비즈니스 로직 / 데이터 접근을 각각 다른 파일로
- 기능별 분리(feature-first) — 기능 단위로 폴더를 묶고 그 안에 UI·로직을 함께
- 관심사 분리(Separation of Concerns) — 화면, 로직, 데이터를 섞지 않기
- 단일 책임 원칙(SRP) — 파일/함수 하나가 한 가지 이유로만 수정되게
- 레이어드 아키텍처 — presentation / domain / data 3계층
- feature-first 폴더링 — 기능 중심 디렉토리 구성
- 데이타 DB방식으로 저장

[기술 스택] 순수 HTML/CSS/JS, ES6 모듈 사용 
프레임워크 확장계획 있음

[서비스 핵심 기능]
- 한국 100대 명산 코스추천
- 산에 대한 주요정보 안내 소개글 
- 등산길 안내
- 내 코스 등록길 저장
- 월별 기록 ( 내가 등반한 코스 저장한것 누적 킬로수 , 클릭시 세부 일정별 산행정보) 
- 카테고리별 필터
- 산행 등정 완료시 배찌 기능

[디자인 요구사항]
-참고 앱 :  트랭글하고 BAC(블랙야크 알파인 클럽)

[참고할 요소 — 원리만]
- 한 화면에 한 가지 작업만 두는 단계별 입력 흐름
- 정보 위계가 강한 타이포 대비 (숫자 크게, 라벨 작게)
- 넉넉한 여백과 낮은 정보 밀도

[참고하지 말 것]
- 아이콘과 일러스트 서체는 동일하지 않고 차별화 되도록
- 화면 레이아웃 및 UI는 완전 동일하게 하지는 않고 일반적으로 하는 방식을 따름

[우리만의 방향]
- 브랜드컬러 : 블루로
- 톤: 차분하고 도구적인 느낌, 귀엽거나 캐주얼하지 않게
- 타이포: 산세리프 1종에 굵기 대비로만 위계 구성
- 컬러: 무채색 기반 + 액센트 1색
- 모서리: 각지게 (라운드 최소화)

[요청] 위 원리를 우리 방향으로 재해석해서 만들어줘. 
참고 앱과 나란히 놓았을 때 '같은 앱 계열'로 보이면 안 됨.

[확장 계획] 추후 로그인, 다중 사용자
- 로그인 방식 : 카카오톡 로그인 , 구글 로그인 , 네이버 로그인 3개방식만 허용

[진행 방식]
1단계: 폴더 구조와 각 파일의 책임을 표로 먼저 제안
2단계: 제가 확인한 뒤 파일 단위로 순차 구현
