# 등산로 경로 데이터

지도에 그리는 선을 어떻게 만드는지, 그 한계가 무엇인지 적는다.

---

## 문제

처음에는 구간 지점(들머리·갈림길·정상)을 **직선으로 이어** 그렸다.
지도 위에서 산을 가로지르는 직선이 되어 실제 등산로와 모양이 전혀 달랐다.

그렇다고 그럴듯한 곡선을 지어내면 더 나쁘다. 근거 없는 선이 **정확한 정보처럼 보이기** 때문이다.
등산에서 길을 잘못 아는 것은 안전 문제다.

## 해결

OpenStreetMap에 실제로 매핑된 보행로를 내려받아 **그 길을 따라** 경로를 만든다.

```
public/data/courses.json (지점 좌표)
        │
        ├─ tools/snap-waypoints.mjs   지점 좌표를 OSM 실제 좌표로 교정
        │      Overpass: bbox 안의 이름 있는 지형지물
        │      이름이 정확히 일치하는 것만, 2.5km 이내에서만 교정
        │
        └─ tools/fetch-tracks.mjs     지점 사이를 실제 길을 따라 연결
               Overpass: bbox 안의 path/footway/steps/track + 접근 도로
               노드 그래프 구성 → Dijkstra (도로에 4배 가중치 → 등산로 우선)
               결과를 course.track 에 기록
```

두 도구 모두 응답을 `.cache/overpass/` 에 저장한다. 재실행 시 API를 다시 부르지 않는다.

### 왜 좌표 교정이 먼저인가

라우팅만 고쳐서는 안 됐다. 손으로 찍은 좌표가 200m~2km씩 어긋나 있어서,
**711m 거리를 2.8km 돌아가는** 경로가 나왔다. 선이 아니라 좌표가 틀린 문제였다.

OSM에는 `대서문`·`도선사`·`장불재` 같은 지점이 이름과 함께 등록되어 있다.
이름이 정확히 일치하는 지형지물을 찾아 그 좌표로 바꾼다.

## 채택 기준

아무 경로나 쓰지 않는다. 아래를 통과해야 `track`으로 저장한다.

| 검사 | 기준 | 이유 |
|---|---|---|
| 지점 스냅 거리 | 600m 이내 | 더 멀면 좌표가 틀린 것 |
| 구간 우회 비율 | 직선거리의 3배 이내 | 엉뚱한 길로 돌아간 것 |
| 전체 길이 | 표기 거리의 0.45~2.2배 | 다른 코스를 탄 것 |

하나라도 걸리면 `track`을 비워 둔다. 그러면 개략 경로로 되돌아가고 **화면에 `개략`으로 표기된다.**
커버리지를 늘리려고 기준을 낮추지 않는다.

## 한계

- **OSM 커버리지에 의존한다.** 등산로가 매핑되지 않은 산은 개략 경로로 남는다.
  국립공원은 대체로 잘 매핑되어 있지만 지방 산은 편차가 크다.
- **실측 GPS 트랙이 아니다.** 매핑된 길을 따라가지만, 그 매핑 자체의 정확도는 OSM 기여자에 달려 있다.
- **코스 선택은 여전히 지점 좌표에 달려 있다.** 갈림길이 많은 산에서는
  의도한 코스와 다른 길로 이어질 수 있다. 길이 검사가 그런 경우를 대부분 걸러낸다.

실측 GPX를 확보하면 `course.track` 에 그 좌표를 넣으면 된다.
`domain/rules/coursePath.js` 가 `track` 을 우선 사용하므로 **화면 코드는 수정할 필요가 없다.**

## 실행

```bash
node tools/snap-waypoints.mjs [산id] [--dry]   # 좌표 교정 (--dry: 미리보기)
node tools/fetch-tracks.mjs   [산id] [--force] # 경로 생성
node tools/verify-data.mjs                     # 정합성 확인
node tools/build-seed-sql.mjs                  # 시드 SQL 재생성
```

Overpass는 공용 서버라 429/504가 흔하다. 두 도구 모두 엔드포인트를 돌며 백오프로 재시도한다.
산을 많이 추가한 뒤에는 한 번에 돌리지 말고 나눠 실행하는 편이 안전하다.

## 출처 표기

OSM 데이터는 ODbL 라이선스다. 지도 하단에 OpenStreetMap과 CARTO 저작자 표시가 항상 노출된다
(`shared/ui/RouteMap.js` 의 `ATTRIBUTION`). 이 표기는 제거하면 안 된다.
