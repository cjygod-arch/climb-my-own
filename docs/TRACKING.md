# 산행 안내 (GPS 트래킹)

'이 코스로 안내받기'를 누른 순간부터 종료까지. 현재 위치가 코스의 어디쯤인지 보여주고,
출발·도착 시각과 총 소요시간을 기록으로 남긴다.

---

## 흐름

```
코스 화면 ─ '이 코스로 안내받기'
   │
   ├─ 위치 권한 요청 (왜 필요한지 먼저 안내)
   ├─ 출발 시각 확정 → HikeSession 생성 → localStorage 저장
   └─ GPS 감시 시작 (watchPosition)
        │
        ├─ 좌표 수신 → 코스 위 진행률 계산 → 세션 갱신·저장
        ├─ 지도: 현재 위치·정확도 원·지나온 자취 갱신
        └─ 패널: 경과 시간·진행률·다음 지점 (1초마다)
   │
   └─ '산행 종료하고 기록하기'
        ├─ 도착 시각 확정, 총 소요시간 계산
        ├─ HikeRecord 저장 (startedAt / endedAt / durationMin)
        ├─ 배지 재평가 (records 서비스 경유)
        └─ 세션 삭제 → 기록 상세로 이동
```

## 계층

| 파일 | 책임 |
|---|---|
| `domain/rules/trackProgress.js` | 위치 → 진행률·이탈 여부·다음 지점. **순수 함수**, GPS도 지도도 모른다 |
| `domain/entities/hikeSession.js` | 세션의 형태와 좌표 누적 규칙 |
| `domain/ports/locationGateway.js` | 위치 인터페이스 |
| `domain/ports/sessionRepository.js` | 세션 저장 인터페이스 |
| `data/browser/location.gateway.js` | `navigator.geolocation`을 아는 유일한 파일 |
| `data/local/session.repo.js` | localStorage 저장 |
| `features/tracking/tracking.service.js` | 위 조각들의 조율 |
| `features/tracking/ui/TrackingPage.js` | 안내 화면 |
| `features/tracking/ui/TrackingBar.js` | 다른 화면에 있을 때의 진행 중 알림 바 |

## 설계 결정과 그 이유

### 세션은 반드시 저장한다

산행은 몇 시간씩 걸린다. 그 사이 화면이 꺼지고, 브라우저가 탭을 버리고, 사용자가 새로고침한다.
메모리에만 두면 그때마다 진행 상황이 사라진다. 좌표가 들어올 때마다 localStorage에 쓴다.

앱을 다시 열면 `bootstrap`이 `tracking.resume()`으로 이어받는다.

### 세션은 로컬에만 둔다

산 위에서는 네트워크가 자주 끊긴다. 통신이 되어야만 진행 상황이 남는 구조는 그 자체로 위험하다.
끝난 세션은 HikeRecord로 변환되어 원격(Supabase)에 저장된다.

### 진행률은 뒷걸음치지 않는다

정상에서 쉬거나 GPS가 튀면 투영 지점이 뒤로 밀린다. `maxAlongM`으로 최대 도달 거리를 기억해
진행률이 줄지 않게 한다.

### 왕복 코스는 직전 위치 근처에서 찾는다

원점회귀 코스는 갔던 길과 오는 길이 같은 좌표를 지난다.
트랙 **전체**에서 최근접점을 찾으면 되돌아오는 내내 '출발점 근처'로 판정되어 진행이 멈춘다.
그래서 `projectOnTrack`에 `fromM`을 주어 직전 진행 지점 앞뒤(뒤 200m / 앞 1,200m)에서만 찾는다.
그 범위에서 코스 위라고 볼 만한 결과가 없으면 그때 전체를 훑는다(진짜로 벗어났다가 다른 곳으로 복귀한 경우).

> 이 처리가 없을 때 북한산성 왕복 코스는 84%에서 멈췄다.

### 지점 안내는 트랙 거리로 잰다

구간에 적힌 `cumDistanceKm`(사람이 적은 값)와 실제 라우팅된 트랙 길이는 다르다(8.2 vs 7.6km).
둘을 섞어 쓰면 '다음 지점'이 어긋난다. `locateWaypoints()`가 지점 좌표를 트랙에 투영해
같은 자로 잰 `alongM`을 만들어 두고, 그것만 쓴다.

### 튄 좌표는 거리에 더하지 않는다

신호를 다시 잡을 때 순간이동처럼 찍히는 일이 있다(터널·계곡). 그대로 더하면
7km 코스가 13km로 기록된다. 초당 5m를 넘는 이동은 거리 합산에서 제외한다(기준점은 옮긴다).

측정된 이동 거리가 코스 거리의 절반에도 못 미치면 GPS가 부실했다고 보고
**코스 표기 거리로 대체**한다. 사용자가 실제로 걸은 길을 0km로 기록하는 것보다 낫다.

### 정확도가 나쁜 신호로 진행률을 올리지 않는다

`accuracy > 100m`인 좌표는 화면에 표시는 하되 진행률 판정에는 쓰지 않는다.
코스 이탈로 판정된 지점으로도 진행률을 올리지 않는다.

### 지도를 직접 움직이면 따라가기를 끈다

보려는 곳을 뺏지 않는다. 다시 따라가려면 '내 위치로 이동' 버튼을 누른다.

## 한계

- **화면이 꺼지면 브라우저가 위치 갱신을 늦추거나 멈춘다.** 웹의 구조적 한계다.
  중요한 산행에서는 화면을 켜두거나 전용 GPS 기기를 함께 쓰는 편이 안전하다.
  (Screen Wake Lock API로 완화할 수 있으나 지원이 고르지 않다.)
- **HTTPS에서만 동작한다.** GitHub Pages는 HTTPS이고 localhost는 예외로 허용된다.
- **경로 좌표가 있는 코스에서만 안내가 가능하다.** `개략 경로`만 있는 코스도 안내는 되지만
  기준선 자체가 개략이라 이탈 판정이 부정확할 수 있다.

| 항목 | 결과 |

| 새로고침 후 세션 유지 | OK (알림 바 표시) |
| 종료 → 기록 저장 | startedAt / endedAt / durationMin 기록됨 |
| 안내 화면에서 알림 바 숨김 | OK |

## 운동(걷기) 기록

코스 없이 걸은 길을 기록한다. 홈의 `운동(걷기)` 버튼 → `/walk/new` → `/tracking`.

### 산행과 무엇이 다른가

같은 세션·GPS·저장 구조를 쓰되, `activityType` 하나로 갈린다
(`domain/entities/activity.js`).

| | 산행 | 걷기 |
|---|---|---|
| 코스 | 있음 | **없음** |
| 지도 | 코스 선 + 내 위치 | **내 자취만** |
| 주요 수치 | 진행률 · 남은 거리 · 도착 예정 | **걸은 거리 · 경과 시간 · 평균 속도** |
| 코스 이탈 경고 | 있음 | 없음 (벗어날 코스가 없다) |
| 지점 안내 | 있음 | 없음 |
| 기록 제목 | 산 이름 | 사용자가 붙인 제목 (기본 `걷기`) |

### 배지와 100대 명산에서 제외한다

`명산 5`나 `누적 100km` 같은 배지 이름은 등산 맥락이다. 동네 산책으로 채워지면
그 배지가 뜻을 잃는다. 그래서 **배지 판정은 산행 기록만** 본다
(`badges.service.js`의 `records.filter(isHike)`).

100대 명산 진행률도 마찬가지다 — 걷기에는 산이 없으므로 자연히 빠진다.

월별 누적 거리와 최근 활동 목록에는 **함께 표시한다.** 사용자 입장에서
"이번 달 내가 움직인 거리"는 하나이기 때문이다.

### 이동 경로를 기록에 남긴다

종료할 때 GPS 좌표열을 `record.route`에 담아 저장하고, 기록 상세에서 지도로 그린다.
좌표는 소수 5자리(약 1m)로 줄여 용량을 아낀다.

### 종료할 때 세션을 마지막에 지운다

처음 구현에서는 세션을 먼저 지우고 기록을 저장했다. 그러면 저장이 실패했을 때
사용자가 걸은 기록을 **통째로 잃는다.** 지금은 기록이 확정 저장된 뒤에야 세션을 지우고,
실패하면 세션을 살려두고 다시 시도하게 안내한다.

### 거리 0인 걷기도 저장한다

실내나 신호가 나쁜 곳에서는 GPS가 잡히지 않아 이동 거리가 0으로 측정될 수 있다.
그때 저장을 막으면 걸은 시간까지 함께 사라진다. 걷기는 거리 0을 허용한다
(산행은 여전히 0보다 커야 한다).

### 검증

`Emulation.setGeolocationOverride`로 서울 시청 일대를 한 바퀴 도는 경로를 재현했다.

| 항목 | 결과 |
|---|---|
| 걷기 시작 화면 → 제목 입력 → 시작 | OK |
| 세션 `activityType: walk`, 출발 시각 기록 | OK |
| 진행률·지점 안내 대신 걸은 거리·평균 속도 표시 | OK |
| 종료 시트: 출발/종료/총 소요시간/걸은 거리 | OK |
| 기록 저장: 제목·출발·도착·경로 40점 | OK |
| 기록 상세에 걸은 길 지도 표시 | OK |
| 배지가 걷기로 채워지지 않음 | 0개 유지 |
| 100대 명산 진행률이 오르지 않음 | 0 유지 |
