# 로그인 정책

**기록하려면 로그인해야 한다. 보는 것은 로그인 없이도 된다.**

다중 사용자 서비스이므로 기록은 반드시 계정에 귀속되어야 한다.
익명으로 만든 기록은 기기를 바꾸면 사라지고, 나중에 계정과 합칠 방법도 마땅치 않다.

---

## 무엇이 막히고 무엇이 열려 있나

| 로그인 없이 | 로그인 필요 |
|---|---|
| 100대 명산 목록·상세·소개글 | 산행 기록 (`/records/*`) |
| 등산 코스·구간 안내·고도 단면 | 운동(걷기) 기록 (`/walk/new`) |
| 코스 지도 | 활동 안내 (`/tracking`) |
| | 내 코스 등록 (`/courses/new`) |
| | 배지 (`/badges`) |

배지를 막는 이유: 배지는 "내가 얼마나 했는가"라서 계정이 없으면 의미가 없다.

---

## 어디서 막는가 — 세 겹

### 1. 라우터 (화면 진입)

`app/routes.js`의 `requiresAuth: true` → `app/bootstrap.js`의 `guard`가 `/login?next=...`로 보낸다.

**화면마다 따로 검사하지 않는다.** 그러면 반드시 하나를 빠뜨린다.
기록 화면을 새로 추가할 때 `requiresAuth`만 붙이면 게이트가 따라온다.

`next`에 원래 가려던 경로를 넣어, 로그인하면 하던 일을 이어서 할 수 있다.
`replace: true`로 보내므로 뒤로 가기를 눌러도 막힌 화면으로 되돌아가 튕기지 않는다.

### 2. 서비스 (인라인 동작)

라우터가 못 막는 것이 있다. 코스 안내 화면의 `이 코스로 안내받기`처럼
공개 화면 위에 있는 버튼이다. `tracking.service`가 직접 확인하고,
화면은 로그인으로 안내한다.

### 3. 저장소 / RLS (마지막 방어선)

모든 쓰기 메서드가 `getUserId()`를 확인하고 없으면 `LOGIN_REQUIRED_MESSAGE`를 돌려준다.

Supabase 모드에서는 여기에 더해 **Postgres RLS**가 `auth.uid()`로 다시 검사한다.
화면과 서비스를 모두 우회하더라도 데이터는 안전하다.

---

## 익명 로그인을 쓰지 않는다

이전 구현은 익명 세션(`signInAnonymously`)으로 `auth.uid()`를 확보해
로그인 없이도 기록할 수 있게 했다. 정책이 바뀌었으므로 두 어댑터 모두에서 걷어냈다.

**Supabase 대시보드에서도 Anonymous sign-ins를 꺼두는 편이 안전하다.**
켜져 있으면 누군가 직접 API를 불러 익명 계정을 만들 수 있고,
그렇게 쌓인 데이터는 주인이 없다.

### 남아 있던 익명 기록은 옮긴다

정책이 바뀌었다고 사용자가 이미 남긴 기록이 조용히 사라지면 안 된다.
로컬 어댑터는 처음 로그인할 때 옛 익명 id로 저장된 기록·코스·배지를
새 계정으로 한 번 옮긴다 (`data/local/auth.gateway.js`의 `adoptLegacyData`).

---

## 개발용 로그인

`config.DATA_SOURCE`가 `'static'`이면 실제 소셜 로그인이 없다.
그래도 게이트가 동작하는지 확인해야 하므로, 로컬 어댑터가 계정을 흉내 낸다.

**흉내라는 사실을 숨기지 않는다:**
- 비밀번호도 검증도 없다. 누구나 어떤 provider로든 들어온다
- `displayName`에 `(개발용)`이 붙어 화면에서 바로 구분된다
- 이 파일은 static 모드에서만 결선된다

덕분에 Supabase를 붙이기 전에도 로그인 흐름 전체를 검증할 수 있다.

---

## 로그인 수단

카카오 · 구글 · 네이버 셋뿐이다 (`domain/ports/authGateway.js`의 `PROVIDERS`).

브랜드 컬러를 쓰지 않는다 — 무채색 + 액센트 1색 원칙을 지키려고
세 버튼을 같은 형태로 두고 이름으로만 구분한다.

네이버는 Supabase 기본 provider가 아니라 Edge Function 브릿지가 필요하다.
그 차이는 `data/supabase/auth.gateway.js` 안에만 존재하고 포트도 화면도 모른다.
자세한 절차는 [supabase/README.md](../supabase/README.md).

## 검증

로그아웃 상태에서 시작해 전 과정을 브라우저로 확인했다.

| 항목 | 결과 |
|---|---|
| 기록 화면 6곳 진입 | 전부 `/login?next=...`로 이동 |
| 공개 화면 4곳 (명산·상세·코스·지도) | 로그인 없이 정상 표시 |
| 로그인 후 | 원래 가려던 `/records/new`로 이어짐 |
| 세션 | `provider: kakao`, `isAnonymous: false` |
| 로그인 후 걷기 기록 | 저장되고 `userId`가 붙음 |
| 로그아웃 | 세션 삭제 + 게이트 재작동 |
| 예외 | 0건 |
