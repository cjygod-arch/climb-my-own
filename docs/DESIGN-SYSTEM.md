# 디자인 시스템

**컨셉: 단순하고 직관적인 도구.** 토스·당근 계열의 부드러운 카드 UI.

한 화면에서 할 일이 하나로 보이고, 숫자가 먼저 눈에 들어오고, 어디를 눌러야 할지 헷갈리지 않는다.

> **방향 전환 기록.** 처음에는 '각진 계측기(instrument)' 컨셉이었다(라운드 0~2px, 1px 헤어라인, 각진 캡 아이콘).
> 실제 화면을 확인한 뒤 토스·당근처럼 단순하고 직관적인 형태로 방향을 바꿨다.
> **유지한 것**: 무채색 기반 + 블루 액센트 1색, 산세리프 1종, 숫자 크게/라벨 작게, 낮은 정보 밀도.
> **바꾼 것**: 각진 모서리 → 라운드, 헤어라인 분할 → 카드 분할, 선 아이콘 → 픽토그램.

---

## 1. 차별화 기준

참고한 것은 트랭글·BAC가 아니라 **토스·당근의 정보 구조**다. 등산 앱 계열과는 여전히 갈라져 있어야 한다.

| 축 | 트랭글 | BAC | **Climb My Own** |
|---|---|---|---|
| 첫 화면 | 지도·기록 버튼 | 인증 사진 피드 | **이번 달 누적 거리 하나** |
| 컬러 | 형광 그린 + 다색 | 블랙 + 옐로우 | 무채색 + **블루 단색** |
| 면 분리 | 그림자 카드 + 사진 | 사진 배경 | **옅은 회색 위 흰 카드** |
| 배지 | 원형 스티커·일러스트 | 원형 인증 마크 | **사각 라운드 타일, 일러스트 없음** |
| 아이콘 | 채색 일러스트 | 심볼 마크 | **단색 픽토그램** |
| 톤 | 캐주얼·게임적 | 성취·이벤트 | **담백·실용** |

**자가 점검:** 스크린샷에서 색을 빼도 위계가 읽히면 성공이다. 색이 아니라 크기와 굵기로 구분한다.

## 2. 컬러 토큰

무채색이 화면의 대부분을 차지한다. 블루는 **액션과 현재 상태에만** 쓴다.

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--c-bg` | `#F2F4F6` | `#101215` | 페이지 배경 (옅은 회색) |
| `--c-card` | `#FFFFFF` | `#191C20` | 카드 (내용을 담는 그릇) |
| `--c-surface-2` | `#E5E8EB` | `#23272C` | 보조 버튼·입력·트랙 |
| `--c-line` | `#EAEDF0` | `#23272C` | 카드 내부 구분선 |
| `--c-text` | `#191F28` | `#F2F4F6` | 본문 |
| `--c-text-mute` | `#6B7684` | `#9AA3AE` | 라벨·보조 |
| `--c-text-faint` | `#8B95A1` | `#6B7684` | 비활성·단위 |
| `--c-accent` | `#3182F6` | `#4A90F7` | 액센트 (유일) |
| `--c-accent-weak` | `#E8F3FF` | `#16243A` | 선택된 행 배경 |
| `--c-danger` | `#F04452` | `#FF6B75` | 경고·삭제 |

**액센트 사용 허용 목록** — 이 외에는 쓰지 않는다.

1. Primary 버튼
2. 활성 탭 / 선택된 칩 / 선택된 코스
3. 진행 표시 (StepFlow 바, 배지 진행률, 추이 막대)
4. 고도 단면 그래프와 지도 경로
5. 포커스 링
6. 획득한 배지 타일

## 3. 타이포

산세리프 **1종.** `Pretendard Variable` → 시스템 스택 폴백.
굵기는 **400 / 600 / 700 세 단계만**.

| 클래스 | 크기 | 굵기 | 용도 |
|---|---|---|---|
| `.t-stat` | 36px | 700 | **주요 수치** (tabular-nums) |
| `.t-display` | 24px | 700 | 페이지 제목 |
| `.t-stat-sm` | 22px | 700 | 보조 수치 |
| `.t-title` | 17px | 700 | 섹션·카드 제목 |
| `.t-body` | 15px | 400 | 본문 |
| `.t-caption` | 13px | 400 | 캡션·보조 설명 |
| `.t-label` | 12px | 600 | 라벨 |

한글이므로 `letter-spacing`은 **음수**로 준다(-0.01 ~ -0.035em). 자간을 벌리면 흐트러져 보인다.

### 숫자 위계

수치와 라벨의 크기비 **3:1** (36px : 12px). 모든 수치는 `tabular-nums`.

```
  128.4 km       ← .t-stat    36px / 700
  이번 달 누적 거리 ← .t-label   12px / 600
```

## 4. 간격 · 밀도

`--space-1`~`8` = 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48px. 페이지 좌우 여백은 20px.

- 한 화면(뷰포트 1개)에 카드 **최대 3개**
- 카드 사이 `--space-4` (16px)
- 카드 내부 패딩 `--space-5` (20px)
- 터치 대상 최소 **48px**

## 5. 형태

| 토큰 | 값 | 용도 |
|---|---|---|
| `--radius-sm` | 8px | 태그·작은 버튼·스켈레톤 |
| `--radius` | 12px | 버튼·입력·목록 행 |
| `--radius-lg` | 16px | **카드** (기본 그릇) |
| `--radius-xl` | 20px | 시트 상단·지도 패널 |
| `--radius-full` | 999px | 칩·마커·진행바 |

**테두리로 나누지 않는다.** 옅은 회색 페이지 위에 흰 카드를 얹어 면을 나눈다.
그림자는 아주 옅게(`--c-shadow`) — 떠 보이게 하려는 게 아니라 경계를 부드럽게 하려는 것이다.

## 6. 아이콘

두 종류를 구분한다 (`shared/ui/icons/paths.js`).

### 픽토그램 (PICTOGRAMS · 면)

**탭바와 메뉴에 쓴다.** 면으로 채운 단순한 상징 형태.

| 항목 | 규칙 |
|---|---|
| 형식 | `fill="currentColor"`, stroke 없음 |
| 크기 | 24×24 viewBox |
| 형태 | 실루엣만으로 알아볼 수 있어야 한다. 내부 디테일을 넣지 않는다 |
| 구멍 | 필요하면 `fill-rule="evenodd"`로 파낸다 (배지의 체크 등) |

작은 크기에서 선 아이콘은 뭉개진다. 탭바처럼 22~24px로 쓰는 자리는 반드시 면으로 채운다.

### 글리프 (GLYPHS · 선)

**액션과 방향 표시에 쓴다.** 선으로 그려야 뜻이 통하는 것들(화살표·더하기·체크).

| 항목 | 규칙 |
|---|---|
| 스트로크 | `2` |
| `linecap` / `linejoin` | **`round`** — 픽토그램의 부드러운 면과 같은 언어 |
| 채움 | `none` |

일러스트·마스코트·이모지는 쓰지 않는다.

## 7. 배지

원형 스티커가 아니라 **라운드 사각 타일**.

- **획득**: 액센트 면 채움 + 흰 글자. 티어가 올라갈수록 진해진다(accent → accent-press → text)
- **미획득**: 흰 카드 + `--c-text-faint` 글자 + 진행률 바. 티어는 안쪽 테두리 두께로 구분

---

## 8. 지도

원래는 지도를 쓰지 않기로 했다가, 코스 위치를 눈으로 확인하고 싶다는 요구로 도입했다.
지도는 트랭글의 핵심 화면이므로 그대로 쓰면 즉시 같은 계열로 보인다.

| 항목 | 우리 방식 | 이유 |
|---|---|---|
| 타일 | **무채색** (CARTO Positron / Dark Matter) | 컬러 지형도를 깔면 화면 인상이 지도 앱에 먹힌다 |
| 마커 | **번호가 박힌 원형 핀** + 옅은 그림자 | 카드 UI와 같은 부드러운 언어 |
| 경로 | 선택 코스만 **액센트 실선**, 나머지는 **무채색 점선** | 코스마다 다른 색을 쓰면 팔레트 규칙이 깨진다 |
| 위계 | 지도는 **별도 화면**(`/mountains/:id/map`) | 상세 화면 위에 얹으면 지도가 주인공이 된다 |

**정보 밀도:** 지점 이름표는 **들머리와 마지막 지점에만** 붙인다. 전체 지점명은 '구간 안내'가 보여준다.
**첫 화면은 그 산의 모든 코스가 함께 보이도록** 전체 경계에 맞춘다.

### 경로의 출처를 반드시 구분해 표기한다

| 종류 | 표기 | 근거 |
|---|---|---|
| 실제 등산로 | `실제 등산로` | OSM에 매핑된 보행로를 따라 라우팅한 조밀한 좌표열 |
| 개략 경로 | `개략` (경고 톤) | 주요 지점을 직선으로 이은 것. **실제 길과 모양이 다르다** |

등산에서 길을 잘못 아는 것은 안전 문제다. 없는 정보를 있는 것처럼 보이게 만들지 않는다.
자세한 내용은 [TRAIL-DATA.md](TRAIL-DATA.md).

## 9. 한 화면 한 작업 (StepFlow)

입력은 반드시 단계로 쪼갠다. 한 화면에 입력 필드는 **1개 그룹**만.

```
1/4  언제 다녀오셨나요        → 날짜
2/4  어느 산인가요            → 산 선택
3/4  실적을 입력해주세요       → 거리 · 시간 · 고도
4/4  남길 말이 있나요          → 메모 (건너뛰기 가능)
```

- 진행 표시는 상단 3px 바 + `1/4` 텍스트. 원형 스테퍼를 쓰지 않는다
- 하단 고정 액션 버튼 1개, 배경은 흰색(카드와 같은 면)
- 각 단계는 자체 검증을 갖고, 실패하면 필드 아래에 이유를 쓴다
- 탭바를 감춘다 (`chrome: 'bare'`) — 입력 중에는 다른 이동 수단을 두지 않는다

## 10. 모션

| 상황 | 처리 |
|---|---|
| 화면 전환 | 없음 (즉시 교체) |
| 시트 등장 | 220ms translateY + 배경 페이드 |
| 버튼 누름 | `scale(0.98)` 120ms — 눌린 느낌만 |
| 진행률·막대 | 폭 변화 300~400ms |
| 값 변화 | 카운트업 애니메이션 금지 |
| 로딩 | Skeleton 면. 스피너 금지 |

`prefers-reduced-motion`을 존중한다 (`reset.css`에서 일괄 처리).
